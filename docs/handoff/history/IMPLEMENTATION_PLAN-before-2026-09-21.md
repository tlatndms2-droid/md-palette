저장소: https://github.com/tlatndms2-droid/md-palette

상태: 0.0.15 Sub 전체 높이 배치·41개 테스트·Sandbox 실제 UI·재시작 및 공개 Release 세 자산 해시 검증 통과. 사용자 BRAT 확인 대기. 0.0.14 사용자 확인 완료. 7단계 미시작.

0.0.14 최신 확정: 새 링크 파일 생성 구현, 저장 위치는 사용자 선택 1번인 Obsidian 새 노트 설정. Card·Connections의 기존 연결 추가 옆과 Folder 빈 공간 우클릭에서 이름 입력 → 저장 위치 확인 → 빈 Markdown 생성 → Main 연결. Folder는 현재 가상 위치에도 배치. 동일 이름은 덮어쓰지 않고 취소·실패는 새 빈 파일과 연결·가상 배치를 남기지 않는다. 다른 작업으로 변경된 파일은 보존하고 오류를 알린다. 실행 전 예상 12~20분, Codex 사용량 중간, 평상시 성능 영향 거의 없음. 실제 Vault·BRAT 자동 확인·7단계 제외. 원본 Planning Pack을 변경하지 않고 이 사용자 확정을 추가 기능 기준으로 삼는다.

0.0.12 당시 확정: HTML 1번 선택. 파일 카드 한 개는 Main Markdown에 링크/임베드/본문으로 삽입한다. 강조·블록은 Main 또는 Sub Markdown과 Sub Canvas에 재사용한다. Reference는 사용하지 않는다. 편집 영역의 실제 드롭 위치에 추가하며 메뉴 취소·대상 변경·지원하지 않는 드롭은 삽입하지 않는다. 기존 카드 정렬과 원본은 유지한다. 실행 예상은 구현 8~12분 + 테스트·빌드 1~2분 + Sandbox·재시작 5~8분 + 기록·Release 1~2분 = 15~24분(재시도 제외)으로 이전 6단계 추정을 대체한다.

0.0.13 최신 확정: 한 번 클릭·Ctrl/Shift 선택 유지. 기본 더블클릭은 마지막 사용 Sub의 현재 탭 교체, Ctrl+더블클릭은 같은 그룹 새 탭, Ctrl+Shift+더블클릭은 추가 Sub 그룹. Main 유지·전체 탭 보존. 각주·URL Links 드래그와 Card → Sub Markdown을 추가한다. 각주 텍스트/실제 각주, URL 주소/제목 링크 및 Sub Canvas 카드를 제공한다. 실행 예상 15~24분(재시도 제외).

최신 확정: BRAT 확인은 사용자가 담당한다. Codex는 필수 검증 후 Release와 자산 확인까지만 수행한다. 5단계 최신 잠정 예상은 구현 12~20분 + 테스트·빌드 4~6분 + Sandbox·재시작 10~15분 + 기록·Release 2~4분 = 28~45분이다. 과거 단계 추정은 현재 실행 시간 근거로 사용하지 않는다.

5단계 최신 확정: Metadata Links에는 본문·속성의 HTTP/HTTPS URL만 표시하며 내부 파일 링크는 제외한다. 웹 링크는 매번 웹뷰어(Sub) / 기본 브라우저를 선택한다. Main 본문·속성의 내부 파일 링크는 Sub에서 열고 같은 파일 탭을 재사용한다. 라벨 관리에는 전체 Vault의 사용 파일 수·파일 목록·라벨 삭제를 제공한다. Ctrl 미리보기는 카드·파일 목록에 한정하며 가상 폴더·버튼·메타데이터 항목으로 확장하지 않는다. 각주·Task 외 원문은 수정하지 않는다. 6단계 드래그는 제외한다.

4단계 확정: 정렬 전체 옵션은 문서를 따르고 메뉴 위치·크기·스타일과 전체 화면 구조는 참조 이미지를 따른다. 이미지의 일부 옵션 표시는 기능 제한이 아니다.

3단계 후속 확정: 모든 속성의 Markdown 연결을 표시하고 Obsidian 기본 Local Graph를 재사용한다. 기본 그래프 안의 설정 UI는 유지한다. 사용자 직접 확인을 위해 Sandbox와 시험 자료를 남기며 자동 종료·원상 복원하지 않는다.

3단계 최초 확정: 사용자의 `문서대로 진행해`에 따라 Connections 검색창·필터는 제외한다.

0.0.11 확정: 승인 HTML의 두 줄 제목 카드를 Folder 전용 새 기본 보기로 추가하며 기존 6가지 보기와 저장된 선택은 보존한다. Main 명령은 기존 지정 명령 ID로 통합하고 같은 Main은 해제, 다른 지정 가능한 Markdown은 새 Main으로 바꾼다. 실제 작업 Vault와 BRAT 확인은 제외한다. 승인 예상은 구현 3~5분 + 검사·빌드 1~2분 + Sandbox·재시작 3~5분 + 기록·Release 1~2분 = 8~14분이다.

## 1. 진행 원칙

전체를 한 번에 만들지 않고 한 구간씩 구현하고 직접 사용해 볼 수 있는 버전을 배포한다.

**구현 → 관련 테스트·빌드 → Sandbox 화면·동작·재시작 검증 → GitHub Release → 사용자 BRAT 설치·확인 → 다음 구간**

- 사용자 확인 전에는 다음 구간 구현을 시작하지 않는다.
- 문제가 발견되면 해당 구간부터 수정·재검증한다.
- 미구현 기능은 릴리즈 설명에 명시한다. 부분 구현을 전체 완성으로 보고하지 않는다.
- 기존 Planning Pack과 최신 사용자 확정 답변을 기능 기준으로 삼는다.
- 2026-09-18 `2단계 진행` 및 `정상 작동했어` 답변으로 이전 단계 확인과 2단계 진행을 승인받았다. 연결 저장 위치는 `문서방식으로 진행` 답변에 따라 Main의 `link note` 속성으로 확정했다.

## 2. 구간별 결과물과 예상 시간

시간에는 해당 구간 구현, 관련 검증, 릴리즈와 보고를 포함한다.

| 구간 | 구현·검증 내용 | 사용자가 확인할 결과 | 잠정 예상 |
|---|---|---|---:|
| 0. 실행 기반·기술 확인 | 플러그인 기본 구성, 격리 Sandbox 준비, 탭 그룹 재배치·Canvas 좌표 처리 가능 여부 확인, 새 공개 저장소 준비 | BRAT 설치·활성화 가능한 초기 버전. 기술 시험 기능은 일반 사용자 화면에 노출하지 않음 | 45~80분 |
| 1. Space·사이드바 | Main 지정·해제, 모든 지원 파일 Sub 열기, 탭 보존·중복 방지·순서 보호·재시작 복원 | Main/Sub 작업 공간 사용 | 55~90분 |
| 2. Card | 연결 파일 수집·추가, 썸네일, 파일 유형·라벨 필터, 선택·다중 선택·순서 변경·보기 방식·저장 | 연결 파일을 카드로 보고 정리하고 열기 | 75~120분 |
| 3. Connections | 역링크·나가는 링크·Main 중심 그래프, 영역 접기·높이 조절·저장 | 관계 탐색과 Sub에서 열기 | 40~65분 |
| 4. Folder | Main별 가상 폴더, 세 가지 보기, 생성·이름 변경·이동·삭제, 탐색·검색·정렬, 연결 추가의 전체 성공·취소 | 실제 파일 위치를 바꾸지 않고 연결 파일 정리 | 65~100분 |
| 5. Metadata | 각주·강조·할 일·블록·링크, 검색·원문 편집, Main 고정·옆 탭 열기 | Main 메타데이터 탐색·수정과 링크 열기 | 28~45분 |
| 6. 드래그로 재사용 | Card→Main, 강조·블록→Markdown·Canvas, 삽입 방식 선택, 정확한 위치·취소·지원하지 않는 대상 확인 | 원하는 위치에 링크·본문·카드를 만들고 원본 유지 | 50~85분 |
| 7. 최종 통합 | 완료 기준 대조, 기능 간 연결·업데이트 후 저장 상태·대량 자료 반응성, 시험용 잔여 요소 정리 | 전체 기획 기능을 사용할 수 있는 통합 버전 | 40~60분 |

전체 최초 잠정 예상: 435~700분, 약 7시간 15분~11시간 40분.

실측 예측이 아니다. 기존 작업량 추정에 첫 저장소 준비와 추가 7회 배포 시간을 더한 값이다. 사용자 확인 대기 및 아직 발생하지 않은 실패·재시도 시간은 제외했다. 0단계와 1단계 실측 후 남은 예상을 보정한다. 문서화 과정에서 이미 수행한 저장소 준비는 이후 남은 시간에 중복 계산하지 않는다.

## 3. 화면과 데이터 규칙

### 화면

확정한 UI 방향은 제공 이미지의 배치와 Obsidian 시스템 테마·강조색이다. 새 시안 이미지는 만들지 않는다.

- 사이드바 상단에서 Link View / Metadata View 전환.
- Link View 안에서 Card / Connections / Folder 전환.
- Card·Connections 상단 연결 추가 버튼, Folder 빈 공간 우클릭 연결 추가 메뉴는 기획서 위치를 따른다.
- Space 역할 아이콘, 메뉴, 간격·비율·정보 밀도를 참조 이미지와 비교한다.
- 가상 폴더 삭제는 실제 파일 삭제가 아니라 내부 항목을 한 단계 위로 옮긴다.
- 문서와 이미지의 실제 기능 차이는 해당 요소만 사용자 확인 후 구현한다. 임의 기능 추가 금지.
- 1단계 추가 확정: Main 본문 링크 클릭 팝업은 사용자 선택으로 보류. 기존 Obsidian 링크 동작을 유지한다.

### 2026-09-20 확정 변경 — 이전 Space·전역 폴더 규칙을 대체

- Main과 Sub만 사용한다. Reference 역할·메뉴·명령과 Main/Sub 활성 파일 교환을 제거한다.
- Sub는 Markdown·이미지·Canvas·PDF·영상 등 모든 지원 파일을 새 탭으로 연다. 같은 파일은 기존 Sub 탭을 활성화한다.
- 새 Main 지정·Main 해제 시 기존 Main/Sub 탭을 닫지 않는다. 이전 역할·아이콘만 제거한다. 이전 Sub는 새 Main의 Sub로 자동 유지하지 않는다.
- Main 탭 우클릭으로 지정 해제한다. 해제 뒤 사이드바는 Main 없음이다.
- Card와 Folder의 파일 제목을 위로 옮기고 크게 표시한다. 가상 폴더 이름과 Tree 목록은 기존 크기를 유지한다.
- Markdown 카드 본문은 렌더링한다. 원문과 일반 파일 열기 동작은 유지하며 임베드는 링크로 표시한다.
- 가상 폴더 구조·파일 배치·Folder 보기 상태는 Main Markdown 경로별 플러그인 데이터로 저장한다. Markdown 본문에 기록하지 않는다.
- 자료.md가 A와 B에 함께 연결되어 있어도 각 문서에서 서로 다른 폴더로 정리할 수 있다. 문서 복귀·재시작 후 각자 복원한다.
- 기존 테스트용 전역 가상 폴더·배치만 초기화한다. 실제 파일·본문·연결·라벨·기타 설정은 유지한다. 새 문서별 정리는 반복 초기화하지 않는다.
- 6단계 재사용 드래그의 대상은 Reference가 아닌 Sub의 Markdown·Canvas로 정리한다. 이번 수정에서 5~7단계는 구현하지 않는다.
- 원본 Planning Pack과 AGENTS에 남아 있는 교환·Reference·전역 폴더 설명보다 이 최신 사용자 확정을 우선한다. 원본 자료와 지침 파일은 수정하지 않는다.

### 데이터와 구현 연결

- 라벨·가상 폴더·보기 상태는 플러그인 데이터에 저장한다.
- link note, 각주 내용, 할 일 체크 변경은 실제 Markdown에 반영한다.
- 라벨·가상 폴더 정리는 Markdown이나 실제 파일 경로를 바꾸지 않는다.
- 단계별 업데이트에서 이전 설정·정리 상태를 보존한다. 예외는 이번에 사용자가 삭제를 승인한 기존 테스트용 전역 가상 폴더·배치뿐이다.
- TypeScript 기반으로 Space·파일 관계·저장 상태·드래그 처리를 각 화면에서 공통 사용한다.
- 외부 개발자용 공개 API는 이번 범위에 추가하지 않는다.

## 4. 검증과 사용자 확인

실제 앱 검증은 obsidian-sandbox-validation의 백그라운드 방식을 기본으로 한다. Sandbox가 없으면 obsidian-sandbox-open으로 먼저 준비한다. 실행 전 해당 스킬 전체를 읽고 따른다.

- 실제 작업 Vault와 사용자 마우스를 조작하지 않는다.
- 버튼·메뉴·선택·드래그를 실제 Sandbox에서 실행하고 화면 결과를 확인한다.
- 설치 빌드·버전을 확인하고 필요한 저장 상태는 같은 Sandbox 재시작 후 확인한다.
- 테스트 자료는 스킬에 따라 백업하고 검증 결과와 함께 유지한다. 사용자 최신 요청에 따라 Sandbox를 열어두며, 종료·정리·복원은 사용자 요청 시에만 수행한다.
- 기존 기능은 변경 영향 부분과 핵심 흐름만 재검증한다. 매 구간 전체 검증을 반복하지 않는다.
- Computer Use로 임의 전환하지 않는다.
- 실행 방법 한 번의 실패를 UI 미검증으로 처리하지 않는다. 스킬의 안전한 대체 경로를 수행한다.
- 대체 경로로도 필수 검증을 수행할 수 없으면 정확한 실패와 미검증 항목을 보고하고 배포를 중단한다.

주요 확인 사례:

- Main 변경 시 일반 탭 보존 및 Space 역할 전환.
- A·B에 연결된 동일 파일이 서로 다른 가상 위치를 유지하고 문서 복귀·재시작 후 각자 복원.
- Main 변경·해제 후 탭 보존, 비 Markdown 파일만 있는 Sub 재시작 복원, 동일 파일 중복 탭 방지.
- 가상 폴더 이동·삭제 후 실제 파일 경로·내용 불변.
- 각주 편집 충돌 시 최신 본문 보호.
- 드래그 취소·잘못된 대상에서 원본과 대상 모두 불변.
- 이전 릴리즈 설정이 업데이트·재시작 후 유지.
- 많은 연결 파일과 Metadata 갱신이 스크롤·타이핑을 심하게 방해하지 않음.

전체 세부 완료 기준은 로컬 MD_Palette_Planning_Pack_Final/14_Acceptance_Criteria.md를 따른다.
